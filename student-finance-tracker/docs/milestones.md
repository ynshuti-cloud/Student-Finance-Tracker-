# Project milestones (M1–M7)

Use this checklist to show progress. Do not mark a milestone complete until you have reviewed the relevant files and tested it yourself.

- [x] **M1 — Understand and plan:** problem, target users, user stories, scope, specification and low-fidelity wireframes are documented in this folder.
- [x] **M2 — Build the page structure:** semantic HTML, transaction form, dashboard, budget panel, records table and settings are in `index.html`.
- [x] **M3 — Style the interface:** responsive layout, form states, cards, table, progress bar and mobile breakpoints are in `styles/style.css`.
- [x] **M4 — Add JavaScript behavior:** validation, calculations, storage, sorting, search, import/export, edit/delete and dashboard rendering are split across `scripts/`.
- [x] **M5 — Add data and tests:** `seed.json` contains 12 example records; `tests.html` runs browser-based helper tests.
- [ ] **M6 — Test and publish:** run all automated and manual tests, fix any issues, then publish with GitHub Pages. Record the real repository and Pages link in your submission.
- [ ] **M7 — Demonstrate the project:** record a 2–3 minute video showing the app working. Follow `demo-script.md`.

## Suggested commit history
If you are using Git, make separate commits as you finish each stage. Example messages:
1. `docs: add project specification and wireframes`
2. `feat: build semantic finance tracker layout`
3. `style: add responsive student dashboard`
4. `feat: add transaction validation and storage`
5. `feat: add search, sorting and JSON backup`
6. `test: add validation and calculation checks`
7. `docs: add testing and deployment guide`

These are suggestions for a genuine development history, not commits to claim unless you actually made them.
